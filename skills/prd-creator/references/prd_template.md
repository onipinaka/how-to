# PRD Template Reference

This reference file provides a quick-reference checklist of all mandatory sections and minimum depth requirements for PRDs generated by the `prd-creator` skill.

---

## Mandatory PRD Sections (All Required)

| # | Section | Minimum Depth |
| :--- | :--- | :--- |
| 0 | Header & Metadata (Version, Status, Author, Date) | 4 lines |
| 1 | Key Assumptions & Inferred Scope | 5+ numbered assumptions |
| 2 | Executive Summary & Core Value Proposition | Problem (3-5 lines), Value Prop, 4+ KPIs |
| 3 | Target Audience, Personas & RBAC Matrix | 2-3 detailed personas (5+ attributes each) + full RBAC table |
| 4 | Atomic Feature Breakdown | **Every module** gets: Overview, 5+ atomic features with IDs (FEAT-X.Y), 3+ user stories, 5+ acceptance criteria checkboxes, P0/P1/P2 priority. Minimum 5 modules. |
| 5 | Complete Screen Hierarchy & Interface States | **Every screen** gets: Route URL, Auth requirement, key components list, 5 interface states (Default, Loading, Empty, Error, Success). Minimum 8-12 screens. |
| 6 | Exhaustive API Endpoint Specification | Full table with HTTP method, route, description, auth level, request/response payloads. **Minimum 15-25 endpoints.** |
| 7 | Full Database Schema & Data Dictionary | **Complete CREATE TABLE statements** for every entity. All columns, types, PKs, FKs, indexes, defaults, constraints. Minimum 5-6 tables. No comment-only placeholders. |
| 8 | Third-Party Integrations & SDK Architecture | Table with provider, SDK, purpose, webhook events for each integration. |
| 9 | Non-Functional Requirements | Performance (latency targets), Security (OWASP, encryption), Scalability (pooling, CDN), Accessibility (WCAG), Monitoring. |
| 10 | Comprehensive Edge Cases & Failure Modes | Table with category, edge case description, and expected behavior. Minimum 12-15 edge cases. |
| 11 | Out of Scope (v1.0) | Explicit list of features deferred to v2. |

---

## Anti-Patterns to Reject
- ❌ Generic 2-3 page summaries
- ❌ Placeholder text: `(similar for other modules...)`, `[add details]`, `...and so on`
- ❌ One module written in detail, others summarized
- ❌ SQL schema with comment-only tables (`-- 3. Projects Table`)
- ❌ API table with 4 rows ending in "continue for all..."
- ❌ Screens listed without the 5-state breakdown
